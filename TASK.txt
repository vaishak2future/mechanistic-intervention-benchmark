Improve MobileLLM's weights so it performs better at tool calling on unseen tasks.

Everything is prepared on an H100. Start with:
  cat /prepared/readiness.json
  cat /prepared/baseline.json
  python /task/train.py --steps 100 --output /workspace/submission

/base contains the starting weights and tokenizer. /workspace is writable and
persists in Modal storage. /task/tasks.json contains development examples.
/task/train.jsonl supplies ten starter answers for those same examples.
The baseline report includes each generated answer and its failure reason.
You may edit scripts, generate more training data, and change training settings.
The starter uses LoRA and saves full merged weights. Its prompt tokens are masked
out of the training loss. It is a starting recipe, not a promise of improvement.

Development evaluation:
  python /task/warm_eval.py --report /workspace/base-eval.json
  python /task/eval.py --model /workspace/submission --tasks /task/tasks.json --report /workspace/candidate-eval.json

The first command uses the already warmed base-model engine. It sleeps between
requests to free GPU memory for training. Compilation caches are prepared in
/cache. CUDA graphs are retained in the live base engine, not stored as files.
A new process or a different checkpoint may still load weights and capture graphs.
Network access is off. PyTorch, Transformers, PEFT, Accelerate, and vLLM are ready.

Submission:
Finish writing /workspace/submission/model.safetensors and tell the operator.
Submission ends your run. Save full merged weights; adapters and pickle files
are not accepted. Only that safetensors file is used. The original configuration,
tokenizer, chat template, and evaluator remain fixed for grading.

Scoring:
A separate evaluator tests hidden tasks, four samples each. Call tasks require
exactly one correctly named JSON tool call with matching arguments. No-call
tasks require no calls and specified answer text. Truncated outputs fail.
Your score is mean task success; improvement is submitted score minus baseline
on the same hidden tasks. The agent clock starts after readiness; the operator
provides the duration and enforces its deadline outside this sandbox.
